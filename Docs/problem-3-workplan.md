# Problem 3 How I would run delivery

I would use one ClickUp board for app adoption, the GTM tracker and the student dashboard. Every feature, automation and analytical upload would follow the same process. I would own priorities and outcomes; the process designer would own usability, data definitions and handoffs; the engineer would own implementation, release and recovery.

**Working** means someone can complete the flow and trust the result. **Successful** means the agreed measure improves and people keep using it. I would check both.

## The six stages

| Stage | What I need before moving on |
| --- | --- |
| Backlog | A clear user problem, evidence and a reason to prioritize it. |
| Ready | An owner, baseline, target, small scope, acceptance checks, release route and review date. |
| Building | One complete journey demonstrated, including measurement and failure handling. |
| Checking | A first-time user — teen, parent or staff member — can find it, understand it and act unaided. Data and recovery checks pass. |
| Pilot | The chosen users have the right version or data, and we have observed the agreed outcome for the full window. |
| Live | An operating owner, fallback and next review date. I record what we keep, improve or stop. |

If a pilot is inconclusive, I run it one more week with a specific question. If it still teaches us little, I change the test or stop spending time on it.

## Worked example from Problem 1

My first focus attempt ended after I switched apps. The Daily Velocity card also showed why finding an action matters: it did not open the relevant work.

The first app change would improve only the guidance before Focus starts. Five students would try it unaided. I would then track session completion and seven-day repeat use against a defined baseline.

Two days is the build estimate. Device testing, approval where required, distribution and checking installation have separate slots. I would confirm the existing TestFlight and Android APK routes first. Remote updating would be used only if already supported and permitted.

Diwali falls on 8 November. I would avoid using the following week as the main student-engagement test. Release, usability and installation checks must pass before the focus pilot; a delay moves its observation window.

Monday: 30 minutes to choose work. Daily: a short ClickUp update. Friday: 30 minutes to demonstrate the flow and review results. I resolve blockers lasting more than one working day.
